# 机制说明：gasleft() 判罚的完整推导

## 背景：为什么之前查不出来

这个 hook 的 `beforeSwap` 有一个反直觉的特性 —— **用 `eth_call` 静态调用，无论传什么参数都返回 fee=0**。

我们扫遍了所有入参：

| 变量 | 扫描范围 | 结果 |
|---|---|---|
| `amountSpecified` | 1 → 1e24，正负both | 全 0 |
| `sqrtPriceLimitX96` | 哨兵值 / 当前价 / ±0.01%~±5% 共 11 种 | 全 0 |
| `zeroForOne` | true / false | 全 0 |
| `hookData` | 空 / 随机 / 4 种构造 | 全 0 |
| `sender` | 真实套利者 / 零地址 / 随机 | 全 0 |
| `tickSpacing` | 4 种 | 全 0 |

而真实链上同一时刻同一个池确实在收 4.8% / 9.5% / 15%。**硬矛盾。**

这个矛盾持续了两轮分析，期间提出并证伪了 12 个假设（金额门槛、价格偏离、影子基准线、白名单、同块顺序、transient storage、swap 计数器周期性……）。

---

## 突破口：把 slot3 调大，而不是调小

`debug_traceCall` 显示判定点在 step 490-497：

```
490 SLOAD  → 0x4c4b40 (5,000,000)   ← slot3
491 LT     → 5000000 < X
495 ISZERO
497 JUMPI  → 不跳转，走免费分支
```

最初的直觉是"slot3 是金额门槛，调**小**应该更容易触发收费"。试了 5000000 → 0，**全部无效**。

真正有效的是调**大**：`slot3 = 2^200` 时，fee 立刻变成 48000。

方向反了 —— 说明 `LT` 的语义是 `slot3 < X`，X 大于 slot3 时免费。所以要触发收费，得让 **X 变小**，或让 slot3 变大。

---

## 关键一步：X 是什么

用二分法精确定位临界点：

```
slot3 = 1125899906817965 → fee = 0
slot3 = 1125899906817966 → fee = 48000
```

`X = 1125899906817966 = 0x3ffffffff9fae`

这个数看起来像 `2^50 - 24658`，一度被误判为"二补数表示的 -24658"。

**真正的答案在 trace 里**：搜索 X 首次出现在栈上的位置 —— step 216 的前一条指令：

```
215  GAS      → 0x3ffffffff9fae   ← X 就是 GAS 指令的返回值
216  SWAP1
```

**X = `gasleft()`。**

---

## 验证：只改 gas limit

固定所有其他参数，只改 `eth_call` 的 gas：

```python
def call_gas(gas):
    return eth_call({..., "gas": gas})
```

| gas | fee |
|---|---|
| 100,000 | 48000 |
| 1,000,000 | 48000 |
| 4,000,000 | 48000 |
| 5,000,000 | 48000 |
| **5,024,658** | **48000** ← 临界 |
| **5,024,659** | **0** |
| 6,000,000 | 0 |
| 10,000,000 | 0 |
| 30,000,000 | 0 |

**临界点 5,024,658 − 24,658 = 5,000,000 = slot3。**

那个困扰了很久的 `24,658` 终于有了解释：**从 tx 入口到 hook 内 GAS 指令执行为止消耗的 gas**。

---

## 为什么 view call 恒返回 0

`eth_call` 默认 gas limit 通常是 3000 万或节点上限，远大于 500 万 →
`gasleft()` 永远 ≥ 5,000,000 → 永远走免费分支。

**这解释了此前所有假阴性。** 不是参数没扫对，是每次调用都自带了一个"我不是套利者"的信号。

---

## 真实世界的验证

从链上取 140 笔真实 tx 的 `gasLimit`：

```
收费笔 (19 笔): min=236,397  max=1,353,600  中位=673,289
免费笔 (121 笔): min=274,893 max=10,000,000 中位=7,500,004
```

**19 笔收费的 gasLimit 全部 < 5,000,000，零例外。**

免费笔中位数 `7,500,004` 这个数字本身就很说明问题 —— 那是某个前端路由的硬编码默认值。同理 `10,000,000`。

### 关于 11 个"误报"

有 11 笔 gasLimit < 5M 但没收费。这不是模型缺陷：

- hook 判的是 **`gasleft()`**（hook 执行到那一刻的剩余量）
- tx 的 **`gasLimit`** 是起点，中间要减去路由、PoolManager、token transfer 的消耗
- 两者差值可达几十万 gas

所以 `gasLimit` 只是 `gasleft()` 的上界近似。用它做预测必然有误报，但**不会有漏报** —— 实测正是如此（19/19 命中，0 漏报）。

## 机制评价

### 巧妙之处

在**不做任何外部调用**的前提下（`CALL`/`STATICCALL`/`DELEGATECALL` 全为 0），实现了对套利者的定向收费。

- 不需要维护白名单（省 gas、免运维）
- 不需要读池价（物理上也读不到）
- 不需要预言机
- 判据完全来自 EVM 自身状态

这解释了此前观察到的"sender 画像呈二元分布"（要么 100% 免费，要么常年挨罚）—— 因为路由的 gasLimit 策略是固定的。

### 致命弱点

**套利者只要把 gasLimit 设到 500 万以上就完全免费。**

代价是 `gasLimit` 提高带来的预留金增加 —— 但在 Arbitrum Orbit 链上 gas 极便宜，且未消耗的 gas 会退还，实际成本接近于零。

这个机制的有效性**完全依赖于对手不知道判据是什么**。属于 security through obscurity。

---

## 对 gen6 设计的启示

如果要做一个抗绕过的版本，判据必须是**攻击者无法自由控制、且与套利收益强相关**的量。候选方向：

1. **afterSwap 真实价格偏离** —— 判"这笔交易实际把价格推了多远"，套利者无法通过调 gasLimit 规避
2. **多信号加权** —— gasleft() 作为其中一个弱信号，配合其他特征
3. **同块序号 / 流动性占比** —— 需要 afterSwap 权限位

关键区别：`gasleft()` 是**行为特征**（可伪装），价格偏离是**结果度量**（无法伪装）。
