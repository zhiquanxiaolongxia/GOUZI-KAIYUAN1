## 一句话结论

**8946B 不是「按价格偏离连续计费」，而是掷骰子：每笔 swap 现场生成一个均匀随机数 `r ∈ [0,9999]`，与三段累积权重比大小决定费率档，最后统一乘一个全局折扣系数。**

```solidity
function beforeSwap(address sender, PoolKey key, SwapParams p, bytes)
    external returns (bytes4, BeforeSwapDelta, uint24)
{
    // ── 关卡一：gas 门（身份过滤）── slot3 = 6,000,000
    if (gasleft() >= 6_000_000)
        return (..., LP_FEE_OVERRIDE | 0);        // 免费放行

    // ── 关卡二：掷骰子 ──
    //   r 已实证为 [0,9999] 均匀分布，且对 1 wei 改动雪崩
    uint256 r = uint256(keccak256(abi.encode(
        blockhash(block.number - 1), block.prevrandao, block.timestamp,
        block.chainid, address(this),   // ★ 比 5131B 多这两项（防跨链重放）
        key, sender, p.amountSpecified, p.zeroForOne
    ))) % 10000;

    // ── 关卡三：三段累积权重选档 ── slot2
    uint256 w1 =  slot2        & 0xffff;   // A: 7000   B: 6000
    uint256 w2 = (slot2 >> 16) & 0xffff;   // A: 1500   B: 1000
    uint256 w3 = (slot2 >> 32) & 0xffff;   // A:  500   B: 1000

    uint24 base;
    if      (r < w1)           base = tierOneFee;    //  50000  = 5%
    else if (r < w1+w2)        base = tierTwoFee;    //  75000  = 7.5%
    else if (r < w1+w2+w3)     base = tierThreeFee;  // 100000  = 10%
    else                       base = 0;             // 免费

    // ── 关卡四：全局折扣（8946B 相对 5131B 的新增设计）── slot6
    if (slot6 & 0xff != 0) {                       // enabled = 1
        uint256 disc = (slot6 >> 8) & 0xffff;      // = 2000
        base = uint24(base * (10000 - disc) / 10000);   // 打八折
    }

    return (..., LP_FEE_OVERRIDE | base);
}
```

⚠️ 唯一未逐字节确认的是 `keccak` 内部**字段顺序与编码方式** —— 见「已知局限」。

## 证据链（四重实证，全部可复现）

所有实验基于 `eth_call` + `stateOverride`，**固定 `block_identifier`**。

### ① 过度识别 80/80 —— 证明标量 `r` 真实存在

先二分 `slot2.w1` 把每个 sender 的隐藏 `r` 逼出来，再用**这一个数**去预测另外 10 组权重配置下的档位。一个参数解释多个独立边界，蒙不出来。

```
sender ...001000 r=9716  ✓✓✓✓✓✓✓✓✓✓
sender ...002eef r=3648  ✓✓✓✓✓✓✓✓✓✓
...
>>> 命中 80/80 = 100.0%
```
含**贴边测试**：`(r,1,1)` 预测 T2、`(r+1,1,1)` 预测 T1 —— 差 1 就翻档，全中，排除「碰巧单调」。

### ② 双路径交叉验证 8/8

两条独立二分路径（扫 `w1` vs 扫 `w2`）逼出的 `r` 完全一致 → `r` 是单一真实标量，非构造伪影。

### ③ 分布均匀性 —— 哈希取模的指纹

```
n=80  mean=5115.1（理论 4999.5）
十桶: [6,10,10,5,7,8,8,10,10,6]
卡方 = 4.25   (df=9, 临界 16.92@p0.05)  ✓
KS   D=0.0564 (临界 0.1521@p0.05)       ✓
```
**任何「按金额/偏离度算」的确定性公式都不可能产生均匀分布。**

### ④ 1 wei 雪崩 + 确定性

| 改动 | r |
|---|---|
| 基准（sender=..beef, amt=-1e16, zeroForOne=true） | 7485 |
| 金额 −2e16 | 5713 |
| 金额 **−1e16+1（差 1 wei）** | **2257** |
| 方向反转 | 112 |
| 区块 −2 | 3091 |
| **同参重复 ×3** | **7485, 7485, 7485** |

1 wei 引发雪崩 → 密码学哈希，不是连续函数。同参完全可复现 → 伪随机，非真随机。

### ⑤ 因果实验：改 storage 看输出（非相关，是因果）

## 🔴 本轮推翻的两个旧结论（方法论教训）

### 推翻一：「连续费率曲线 / 按金额分档 0.579%」是**错的**

旧结论称实收费率为 0.579% / 0.804% / 1.099% 三档「按金额分档的连续曲线」。

**错因**：把事件 `data[0]` 当成 1e6 精度费率读。重拉全量后发现该字段 **33/35 条恒为 10417**。
一个「费率字段」不可能 94% 样本完全相同 —— 那些碎数是**解码偏移错误**的产物。
`topic[3]` 也不是「token或0」，而是 **currency 地址**。

真相：storage 里的 5% / 7.5% / 10% **就是**真费率档，只是被 slot6 打了八折成 4% / 6% / 8%。

### 推翻二：「A tierOneFee=55000(5.5%)、B=50000」

两者 slot1 **逐位相同**，都是 50000。

### 教训

- **恒定值 = 解码错误的警报。** 94% 样本同值还当变量用，等于拿常数当证据。
- 上一版教训写着「别信 storage 静态值」，结果矫枉过正 —— 真相恰恰是 storage 值就是真费率。
  **两次都错在没做因果实验，而不是错在信/不信 storage。**
- 字段语义必须靠 **stateOverride 因果实验反证**，不能靠「数值量级看起来像」。

## 🕳️ 踩过的坑（最贵的资产）

### 坑 1：`eth_call` 默认打最新块 = 每次重掷骰子 ★最坑

目标用 `blockhash/timestamp/prevrandao` 做伪随机，不固定 `block_identifier` 则**每次调用结果都不同**。
症状：扫「金额 → 费率」看到一堆变化，误判成「金额影响费率」。**真相是块变了，骰子重掷了。**

**铁律**：任何参数扫描前，先**同参数重复 10 次**验证确定性。不全同 → 立刻固定区块重来。

⚠️ 还要区分「进种子」和「决定结果」：金额进 keccak 会让结果变，但那是**重掷骰子**，
不是「金额越大费率越高」。**要证因果只能改 storage，不能改入参。**

### 坑 2：返回值里的标志位

V4 lpFeeOverride 带 `0x400000` 标志。原始返回 `4194304` 看着像 419%，减掉才是真费率 0。
**任何「荒谬的大数值」先怀疑是标志位。**

### 坑 3：V4 hook selector 漏了 sender 参数

```
beforeSwap(address,(address,address,uint24,int24,address),(bool,int256,uint160),bytes)
  = 0x575e24b4        ← 第一个参数是 sender，漏了一路 revert
```
且 `eth_call` 的 `from` 必须设成 PoolManager，否则 `onlyPoolManager` 直接挡掉。

### 坑 4：`0x8fd0b484` 曾被误标为 `defaultFee`

它返回 6,000,000，实际是 **gas 门阈值 getter**。真 `defaultFee` = `0x5a6c72d0`，值为 0。

## 对自研 hook 的启示

- **折扣系数设计值得抄**：`base × (10000-disc)/10000` 让 owner 不改档位就能全局调松紧，招商期可先打低折扣拉人。
- 但 10% 上限 × 八折 = **8%**，仍贴着三代实测的 **9.9258% 滑点崩溃临界**。罚金上限守 8~9% 的结论不变。
- **加 chainid+address 进种子只防跨链重放，同块 MEV 依旧可预测**（骰子材料全是当块公开值）。可绕过性没有改善 —— 招商材料里必须讲明，别让 LP 以为是铁桶阵。
- gas 门同样可绕：套利者提高 gasLimit 即免费通行。
