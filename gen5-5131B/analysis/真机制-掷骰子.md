# 真机制：gas 门 + 掷骰子

> 本文推翻了前一版「gasleft() 是唯一判据」的结论。前一版不是全错，是**只看到了一半**。

---

## 完整机制

```solidity
// 关卡一：gas 门
if (gasleft() >= 5_000_000) return 0;        // 免费放行

// 关卡二：掷骰子
r = keccak256(blockhash, prevrandao, timestamp, number, poolId, nonce) % 10000;
if      (r < 7500) fee = 48000;   // 4.8%   75%
else if (r < 8500) fee = 95000;   // 9.5%   10%
else if (r < 9500) fee = 150000;  // 15%    10%
else               fee = 0;       // 免费    5%
```

---

## 前一版错在哪

第一轮实验全部 fork 在 **33147572** 这一个块高。在那个块，掷骰子的结果恰好稳定落在 tier1 区间，导致我观察到：

- gas < 5M → 恒 48000
- gas ≥ 5M → 恒 0

于是得出「二元判据」的结论。**单块高采样 = 随机数被冻结**，这是方法论错误：伪随机的输入（blockhash/timestamp/number）在同一个 fork 块高下全部是常量，骰子每次都掷出同一个点数。

### 打破僵局的一步

把 fork 换到 `33285336`（那笔 150000 的前一块），同样参数、同样 gas，fee 变成了 **95000**。

gas 完全没变，fee 变了 → **gas 不是唯一判据**，立刻证伪自己。

---

## 证据链

### 1. opcode trace 直接抓到取模

`debug_traceCall` @ 33285336：

```
step 983   KECCAK256 -> 0xe2da04e76488947a...
step 1007  MOD    keccak % 10000        -> 8377      ← 骰子点数 r
step 1032  AND    slot2 & 0xffff        -> 7500      ← thrA
step 1050  AND    slot2>>16 & 0xffff    -> 1000      ← thrB
step 1076  AND    r & 0xffff            -> 8377      ← 参与比较
```

`MOD(x, 10000)` 是决定性的 —— 除了生成 0~9999 的概率变量，没有第二种解释。

### 2. 伪随机的输入

trace 中的环境 opcode：

| opcode | 值 |
|---|---|
| `BLOCKHASH` | `0x…351aec94680ed0b4` |
| `DIFFICULTY`(PREVRANDAO) | 非零 |
| `TIMESTAMP` | 1786413638 |
| `NUMBER` | 33285336（读了两次） |

全部是**同块内 MEV 搜索者可预知**的值。这是弱随机，不是安全随机。

### 3. 60 次受控采样：边界零重叠

固定 sender / gas / 块高，只改金额（金额本身不进定价，但会扰动 keccak 输入）：

| fee | n | r 实测范围 |
|---|---|---|
| 48000 | 43 | 266 – 7460 |
| 95000 | 8 | 7549 – **8362** |
| 150000 | 8 | **8576** – 9248 |
| 0 | 1 | 9794 |

边界 **7500 / 8500 / 9500** 全部落在实测间隙中，零样本越界。

### 4. 链上 51 笔收费实测 → 卡方检验

模型预测（收费条件下）：75% / 10% / 10% → 归一化 78.9% / 10.5% / 10.5%

| fee | 实际 | 实际占比 | 模型 |
|---|---|---|---|
| 48000 | 43 | 84.3% | 78.9% |
| 95000 | 5 | 9.8% | 10.5% |
| 150000 | 3 | 5.9% | 10.5% |

**卡方 = 1.256，df=2，临界值 5.99 @95%** → 不拒绝模型。

### 5. 同一 sender 跨三档 —— 证伪一切确定性模型

```
0xa687b664662b96b18034   n=38   {48000: 30, 95000: 5, 150000: 3}
```

同一个地址，同一个池，出现全部三档费率。

- 身份白名单模型 ❌ 无法解释
- 金额分档模型 ❌ 无法解释（150000 档里既有 2983 万也有 4.4 亿）
- 价格偏离模型 ❌ 无法解释（hook 零外部调用，看不见池价）
- **掷骰子模型 ✅ 天然预测「同址必然跨档」**

## 关于「参考价偏离」假说

小杨提出的「hook 内部维护参考价锚点，比较成交价偏离度分三档」—— **对这份 5131 字节的合约不成立**。

三条独立否证：

1. **零外部调用**：trace 确认 `CALL/STATICCALL/DELEGATECALL/EXTCODESIZE/BALANCE` 全部为 0。hook 物理上读不到 PoolManager 的 slot0，拿不到当前 tick 和 sqrtPrice。
2. **无价格状态**：全部 SLOAD 只碰 5 个槽 —— owner / 费率配置 / 阈值 / gas门 / swap计数器。没有任何槽存放价格锚点，也没有 SSTORE 写入价格。
3. **同址跨档**：若按偏离度确定性分档，同一地址同方向的单子不应随机落在三个档。

但他的**方向性直觉是对的**：他指出「slot3 那个 5,000,000 很有 gas 量纲」—— 这条命中了关卡一。

同时需要说明：`0x497D…500c4`（8946 字节，权限 0x00c4，带 afterSwap）是**另一套代码**，本文结论不适用于它。偏离度机制在那套里是否存在，需要单独逆向。

## 这机制为什么能赚钱

两道关卡各司其职：

**关卡一是身份过滤器。** 套利机器人为压成本会精确估算 gasLimit（实测 23万~135万），普通前端路由给默认余量（7,500,004 / 10,000,000 一眼就是默认值）。于是 `gasleft()` 成了「来者是不是套利者」的天然指纹——不需要白名单，不需要预言机，零外部调用。

**关卡二是随机抽罚。** 不是每笔都罚，而是概率抽。这带来两个效果：

- 套利者无法通过「这笔被罚了就撤」来规避，因为下一笔仍是独立掷骰
- 对手方难以逆向出规律，看起来像是「有时候收费有时候不收费」的玄学

---

## 致命弱点

| 弱点 | 绕过成本 | 后果 |
|---|---|---|
| gas 门可绕过 | 把 gasLimit 提到 ≥ 5M，Orbit 链 gas 极便宜 | **永久免费** |
| 伪随机可预测 | 同块内 blockhash/prevrandao/timestamp 已知，MEV 搜索者可预先算出 r | 只在 `r ≥ 9500` 时提交 |
| 两者叠加 | 任选其一即可 | 机制归零 |

**结论：这套机制的收益完全建立在「对手不知道判据」之上。** 一旦判据公开（比如本报告），它的护城河就没了。

不建议直接用于招商产品。要做长期有效的机制，随机源必须不可预测（commit-reveal / VRF），或者判据必须是攻击者无法伪造的经济量（真实价格偏离、真实滑点）。
